# 人物状态与行囊一致性界面合同

## 玩家问题与入口

- 玩家在正文页首先需要知道三项核心数值；顶部状态栏保持常驻、每项至少 `44×44px`，点击任一数值进入同一套“世界记录”抽屉中的主角详情。
- 点击的数值在详情页高亮，但详情始终展示全部三项数值、上下限、当前位置、时间、剧情段落数、同行者数量、行囊物品总数和当前目标。
- 主角详情底部提供地图、行囊、记录三个入口；切换的是同一个世界抽屉状态，不建立第二套数据面板。

## 物品状态合同

- `StorySave.inventory` 是行囊唯一真源；叙事文本不能代替物品状态。
- AI 明确叙述玩家获得、收下、装入、交出、失去、丢弃或消耗物品时，同一回复必须输出对应的 `inventory add/remove` 命令。
- 本地 reducer 只对叙述中无歧义的所有权变化做安全补记；“看见、发现、检查”不算获得，含“可以、也许、could、might”等可能性表述不触发补记。
- 获得或失去成功后必须同时写入存档并在对话中显示变化反馈；移除不存在的物品不得伪造“失去”反馈。

## 状态与响应式

- 状态栏支持默认、按下、键盘焦点、警告和危险状态；不能只靠颜色表达数值，始终显示数字和进度。
- 世界抽屉在 `390×844` 与 `320×568` 内部滚动；顶部返回和关闭按钮保持可达，详情内容不得水平溢出。
- 中英文标签均来自现有 i18n 字典，长地点、目标和用户名允许换行或截断，不扩大页面宽度。
